# OmniForge Lab PTY descendant-stop canary — 2026-09-25

Host: Windows, Node 24.19.0, `node-pty` 1.1.0, PowerShell 7, local disposable project. This probes the Lab's interactive terminal lifecycle; it does **not** test Claude/Codex agent containment or Docker isolation.

The initial implementation called `node-pty.kill()` and marked a session stopped after the PTY shell emitted `onExit`. A bounded canary started one long-lived PowerShell child with a unique marker from that shell, verified its parent PID, then requested stop. `onExit` fired, but a fresh Windows process inspection found the marked child still running. The `node-pty` descendant-list helper printed `AttachConsole failed` during cleanup. The experimenter rechecked the exact child PID, parent and command marker, stopped only that child, and confirmed it was gone. No unrelated process was stopped.

**Verdict for the initial implementation: fail.** PTY shell exit is insufficient evidence for descendant cleanup. A repaired stop must require confirmed tree termination and observed shell exit before `stopped`; uncertainty must become `interrupted` and block implicit restart. A new positive and negative canary is required before any cancellation claim. This terminal path runs on the host and must never be presented as the sandboxed agent executor.

Repaired-stop checkpoint: `PtyCoordinator` now invokes Windows `taskkill.exe /PID <owned-shell-pid> /T /F` and waits for both its success and the PTY's observed exit. A failed or timed-out tree request persists `interrupted`; startup/final-status persistence failures also fail closed. At this dated repair point, the standard Lab suite passed **22/22, zero skips** with the repository's serial Node test runner; later suites are recorded in [Lab status](../omniforge/LAB.md) and [T13 validation](../t13/VALIDATION.md). The opt-in real **direct-child** canary passed **1/1**, zero skips, under the approved host execution profile: it verified the child identity before stop and verified the exact child PID absent afterward. Command: `$env:OMNIFORGE_PTY_DESCENDANT_CANARY='1'; node --test --test-name-pattern='descendant canary' omniforge-lab/test/pty.test.mjs`. The sandboxed profile cannot confirm Windows process-tree termination, so its failing close is not counted as a host cancellation result. `node-pty` still prints `AttachConsole failed` while releasing ConPTY handles after the verified tree stop; that diagnostic needs a dependency-level fix before clean presentation.

Independent negative canary after repair: owned PTY shell PID `39196` started an intermediate PowerShell PID `42872`, which spawned long-lived PID `34580` and exited. CIM confirmed the grandchild still had parent PID `42872` while that intermediate was gone. A later `taskkill /PID 39196 /T /F` succeeded and the PTY observed shell exit, so the app stored `stopped`, but a fresh CIM check found PID `34580` still active with the unique test marker. The reviewer identity-checked and stopped only PID `34580`, then removed the verified disposable fixture. **Result: the stop covers the shell and descendants still enumerable beneath it; it cannot certify descendants orphaned by an exited intermediate.** The UI labels the state “shell encerrado.” This host-terminal path cannot satisfy V1 agent/sandbox cancellation; use a verified container or Windows Job Object boundary and retain a negative orphan test before claiming all-descendant isolation.
