# Reusable agent arsenal

Five original portable profiles live in `harness/agent_profiles.json`: engineering builder/reviewer, OS coordinator, scientific auditor, educational challenge validator and technical evidence editor. Their skill references resolve to existing repository skills. Profiles describe context, inputs, outputs and suggested tools; they do not install a host agent, grant authority or dispatch a model.

The stdlib `harness.agent_arsenal` registry stores immutable versions, source references/hashes, exact source-to-rule review, activation/disable/rollback events and task-bound profile copies. A task keeps its pinned version after a profile changes. Writes use a cooperating-writer lock, expected registry revision and atomic replacement. Stale writes fail instead of overwriting another session. Actor labels and sanitization attestations are caller assertions, not authenticated approvals or a secret scanner.

Use `python -m harness.agent_arsenal builtins` to inspect the bundled profiles. The [Agent Forge skill](../../.agents/skills/agent-forge/SKILL.md) gives the authoring/review procedure and registry API. CLI mutation commands require an explicit store and JSON argument file. Built-ins enter as drafts and need review before activation. Disable stops future instantiation; it does not cancel tasks already using a profile. Rollback can recover an earlier reviewed version after disable without erasing history.

Derivation accepts only explicitly selected, sanitized excerpts. Accepted decisions become candidate rules; rejected, experimental and quoted material contributes labeled provenance only. The original selected text stays outside the shared registry except for accepted rule text. A generated candidate remains a draft. Source classification and approval cannot be inferred from the imperative wording of a quotation. No operation discovers other chats or exports a private transcript.

The registry is deliberately bounded: 32 profiles, 16 versions per profile, 128 task pins, 1,024 events and a 2 MiB file. Reaching a bound refuses a write while retaining history; it is not silent pruning. Exact-intent routing is a deterministic lookup, not semantic agent selection. Every result remains `runnable: false`; the existing executor independently applies task scope, availability and host policy.

Current evidence is fixture-based: `python -m unittest tests.test_agent_arsenal` exercises five-pillar coverage, review/version binding, replay, conflicts, immutable pins, disable/rollback and selected-source rules. The first review found that disable discarded the version needed by rollback; a separate retained prior-version field and regression checks repaired it. UI selection, actual attributable task instantiation and an owner-selected session derivation remain required integration/acceptance work, not completed by these fixtures.
