## Observable acceptance for this slice

1. An authenticated Lab page shows the five installed original agent templates and the selected project's saved registry. Import creates a **draft**. The user can preview the full version, source-to-rule map, inherited template settings and immutable content hash; only a separately reviewed version may activate. Disable and rollback preserve history. A stale registry revision refuses mutation rather than silently replacing it.
2. A new profile derives only from **explicitly selected session-scoped memory notes** of the current project. The server resolves note IDs, session IDs and expected note revisions from `WorkspaceStore`; the browser never supplies arbitrary source text to the generator. One to sixteen selected notes, at least one accepted decision, exact classification (`accepted_decision`, `experiment`, `rejected`, `quoted`) and explicit sanitization attestation are required. Rejected/quoted/experimental text contributes provenance, not behavioral rules. Overlong text fails rather than truncates. Cross-project, archived, changed or unselected notes fail.
3. The candidate remains a draft. The page displays every generated rule with its source IDs/reference/hash, requires affirmative review of **each** rule plus inherited settings, and then records review for that exact version/hash. A mechanically copied `sourceRules` map alone is not human review; the UI must make review deliberate and clear about caller-attested identity.
4. The owner selects an existing project task and a host preference and pins only an active reviewed profile to that task. The immutable pin records the chosen version and hash and reports `runnable:false`. It does not dispatch a model, grant tool permissions, certify host containment or mark a task complete. A task's pin is visible in the Lab and stays project-scoped.
5. Registry files are separate per canonical project UUID under Lab `dataDir/arsenal/`; raw selected note text is not copied into the global state/SSE event or another project. Existing token/cookie and same-origin POST protections cover the endpoints. All user text is rendered with DOM text nodes, and stale asynchronous responses cannot display another project's private data.
6. Focused tests exercise successful lifecycle and negative cases: cross-project source/task, stale source/registry revision, archived note, quoted/rejected injection, incomplete review, inactive pin, unknown host preference and stale project UI response. Run the full zero-skip `scripts/check.ps1` afterward. The known two owner-preserved Claude ask/deny install differences remain a separately reported aggregate failure, not skipped tests.
