# OmniForge research: sessions, context, generated UI and optional capabilities

Date: 2026-09-25. Method: public primary-source README, documentation, selected code and license reads, plus the local handoff/contracts. This is an intake assessment, not a full source audit, reproduced benchmark, Windows certification or dependency installation. Three native research agents assisted; attributable token consumption and monetary cost for this research are unavailable, not zero.

The [plan](../omniforge/PLAN.md) records owner decisions and ordering: finish pending E1/T13 execution/accounting/isolation first, then run the approved desktop comparison. These references do not replace that prerequisite. No external repository code was executed, credentials read, service installed or private project material uploaded.

## Sessions and terminals

- [Wave Terminal](https://github.com/wavetermdev/waveterm) is an Apache-2.0 Windows/macOS/Linux terminal with rearrangeable terminal, editor, browser and AI blocks. Its `wsh` interface is a useful reference for workspace operations. Use its layout and lifecycle patterns; its AI-provider configuration does not establish reuse of the owner's subscriptions, and terminal layout does not provide shared agent memory or OS containment.
- [xterm.js](https://github.com/xtermjs/xterm.js) provides terminal rendering; [node-pty](https://github.com/microsoft/node-pty) provides process/PTY integration, including Windows ConPTY. They are candidates for an own desktop implementation, not complete session managers. Resize, cancellation, output buffering, process ownership, restart and attribution still need an application contract.
- [ai-memory](https://github.com/akitaonrails/ai-memory) was already deferred in our [local integration note](../integrations/ai-memory.md). Its current documentation describes a Git-backed Markdown wiki, derived indexes, hooks/MCP, explicit handoffs and a default path without model calls. This is a better candidate for cross-host continuity than a transcript viewer alone; upstream descriptions remain unverified on this host.
- Its [Windows guide](https://github.com/akitaonrails/ai-memory/blob/main/docs/windows.md) still labels native Windows experimental. Its [scope guide](https://github.com/akitaonrails/ai-memory/blob/main/docs/auto-scope.md) says static MCP configurations may not transmit the current agent session identity: concurrent windows by the same user need explicit workspace/project arguments or a session-aware bridge. Our acceptance must test this rather than assume per-user authentication separates sessions. Its [security model](https://github.com/akitaonrails/ai-memory/blob/main/SECURITY.md) is a shared trust domain, not proof of tenant isolation.

Design inference: share discoverable memory and capability metadata through explicit identities, retrieve a bounded brief for each task, serialize/reconcile writes, and keep each terminal's process/worktree identity separate. Restoring a window, reattaching a terminal and resuming a model invocation are three different operations.

## Context loading and AGENTS.md

The [Agent Skills specification](https://agentskills.io/specification) describes progressive disclosure: metadata first, full instructions on activation, resources when required. Reuse this pattern with our capability graph instead of injecting every skill body. Keep mandatory owner/project rules outside relevance-only retrieval. Test both missing critical context and irrelevant retrieved context; compare actual delivery quality as well as token consumption.

The [Coldtea field study](https://www.coldtea.ai/blog/agents-md-field-study) describes the 100 most-starred repositories with a root AGENTS.md, fetched on August 21. Classification uses headings/keywords and excludes redirected content from length statistics. It is descriptive, not an experiment proving that a longer rule file improves agents. Useful lesson: retain project orientation, runnable checks and links to detailed documentation. Do not import its generic template's per-install/per-commit confirmation rules over this owner's standing task authority.

## UI adjusted by chat, including new logic

[A2UI](https://github.com/a2ui-project/a2ui), reached through the former Google repository URL, describes declarative JSON resolved against an application-owned component catalog. Its README lists a stable v0.9 protocol family while still describing the project as evolving public preview. It is a candidate for composing panels, forms and graphs, not a mechanism that safely executes arbitrary generated code. Permission enforcement remains the application's responsibility.

The owner also wants **new mini-tool logic in the first prototype**. Proposed test: generate an asset inventory/relationship checker against fixture files, with its own module manifest, tests, scoped execution, preview and disable/revert path. Keep ordinary panel layout separate from executable extensions. UI generation cannot modify authority/eval rules or obtain direct coordinator/credential access. Layout changes should be requested, reversible and savable; preserve stable navigation and focus mode.

### Coordination and coding-host references

Paperclip's [adapter contract](https://github.com/paperclipai/paperclip/blob/master/docs/adapters/overview.md) separates server execution/parsing from transcript presentation and CLI formatting. Its [installation guide](https://github.com/paperclipai/paperclip/blob/master/doc/INSTALLING.md) and [service guide](https://docs.paperclip.ing/reference/cli/service/) distinguish WSL2 from native Windows, where managed service lifecycle is unavailable and foreground operation is documented. [MIT license](https://github.com/paperclipai/paperclip/blob/master/LICENSE). Borrow explicit task/workspace/host identities; do not inherit a second budget or authority system without reconciliation.

OpenHands now describes an Agent Canvas beta, with React surfaces and execution delegated to AgentServer/SDK. [Architecture](https://github.com/OpenHands/OpenHands/blob/main/docs/architecture.md). Its [Windows example](https://github.com/OpenHands/OpenHands/blob/main/README.windows.md) uses Docker and a projects volume; access to that whole volume does not prove per-project containment. Reusable frontend entries still need compatibility work with our backend. [MIT license](https://github.com/OpenHands/OpenHands/blob/main/LICENSE).

MetaGPT's [installation guide](https://docs.deepwisdom.ai/main/en/guide/get_started/installation.html) and [manifest](https://github.com/FoundationAgents/MetaGPT/blob/main/setup.py) require Python below 3.12, unlike our selected runtime. Its role/action/message patterns are useful references; any execution would need a separate environment. Do not copy a privileged Docker example into our containment profile. [MIT license](https://github.com/FoundationAgents/MetaGPT/blob/main/LICENSE).

Continue's [context guide](https://docs.continue.dev/guides/codebase-documentation-awareness) emphasizes tool-driven search/rules/MCP and deprecates older context-provider paths. Its [configuration reference](https://docs.continue.dev/reference) remains useful for composable configuration, but must be read alongside the final-release README because documentation surfaces can lag. AgentGPT's [archive status](https://api.github.com/repos/reworkd/AgentGPT) and [backend requirements](https://github.com/reworkd/AgentGPT/blob/main/platform/README.md) reinforce its historical-reference role.

### Dify: a specific use without a second core

Its [API guide](https://docs.dify.ai/en/api-reference/guides/get-started) supports application calls; a future module could invoke one published AEO/SEO workflow and return its output, artifacts and execution identity to OmniForge. Keep the credential in the backend. [Self-hosting](https://docs.dify.ai/en/self-host/deploy/quick-start/docker-compose) is a multi-service Docker deployment; Windows instructions use WSL2/Docker Desktop. Its [model configuration](https://docs.dify.ai/en/cloud/use-dify/workspace/model-providers) does not establish automatic reuse of Claude/Codex allowances.

The [Dify license](https://github.com/langgenius/dify/blob/main/LICENSE) adds conditions to Apache-2.0, including multi-tenant use (defined using workspaces) and frontend branding. Backend-only use has a stated exception to the frontend branding condition, not a blanket exemption from all conditions. Confirm the intended deployment/distribution before incorporating it. This is a source-text finding, not a conclusion that any particular commercial configuration is licensed.

### RAGFlow and AstrBot

RAGFlow has both [retrieval](https://github.com/infiniflow/ragflow/blob/main/docs/references/http_api_reference.md#retrieve-chunks) and a [memory subsystem](https://github.com/infiniflow/ragflow/blob/main/docs/guides/memory/configure_memory.md). Proposed initial use is scoped retrieval with cited chunks; inspect HTTP status and the API's own result code. Its README's current requirements include 16 GB RAM, 50 GB storage, Docker and Python 3.13+ for the relevant source environment. Keep it independent of the harness's selected Python 3.12 runtime. Extraction/embeddings may introduce models and consumption of their own. License: [Apache-2.0](https://github.com/infiniflow/ragflow/blob/main/LICENSE).

[AstrBot Desktop](https://github.com/AstrBotDevs/AstrBot-desktop) documents a Tauri/Rust shell, WebUI and CPython backend, with local data, readiness, stop/restart and update channels. These are concrete packaging/lifecycle patterns for our comparison. [Architecture](https://github.com/AstrBotDevs/AstrBot-desktop/blob/main/docs/architecture.md). Both [AstrBot](https://github.com/AstrBotDevs/AstrBot/blob/master/LICENSE) and [Desktop](https://github.com/AstrBotDevs/AstrBot-desktop/blob/main/LICENSE) use AGPL-3.0; study versus code incorporation are different decisions. Its [context compression](https://docs.astrbot.app/use/context-compress.html) is separate from knowledge retrieval and does not establish complete accounting for our loop.

### Review and voice

OpenCodeReview's [delegation documentation](https://github.com/alibaba/open-code-review/blob/main/pages/src/content/docs/en/integrations/delegate.md) describes deterministic preview/rule selection consumed by the coding host. This path avoids a separate OCR model endpoint; it still consumes the host's allowance. Normal managed review has different provider requirements. Its [delegate implementation](https://github.com/alibaba/open-code-review/blob/main/cmd/opencodereview/delegate_cmd.go) exports coverage/schema/ref metadata. Compare with our existing review flows rather than assuming an upstream token-saving claim transfers. License: [Apache-2.0](https://github.com/alibaba/open-code-review/blob/main/LICENSE).

ChatTTS code uses AGPLv3+, while the [official model card](https://huggingface.co/2Noise/ChatTTS) specifies CC BY-NC 4.0 weights. The README targets English/Chinese; PyTorch/model dependencies are substantial. Do not assume those weights are available for the intended commercial distribution or that Portuguese speech has been validated.

PowerShell setup and Windows subprocess handling exist, but were not exercised here; the HyperFrames path requires newer Node than the generic README minimum.

First proposed use after T13: a [screen-demo](https://github.com/calesthio/OpenMontage/blob/08e2151fa02de28a5d6a312b3d575692bf147ad7/pipeline_defs/screen-demo.yaml) based on a real validated run. Label synthetic terminal footage as illustration. Use an independent environment and validate exact render artifacts and failures. Its root [license is AGPL-3.0](https://github.com/calesthio/OpenMontage/blob/08e2151fa02de28a5d6a312b3d575692bf147ad7/LICENSE); [Remotion licensing](https://www.remotion.dev/docs/license), model, asset and provider terms remain separate. ## What this research changes

It adds explicit session/project identity, multi-terminal layouts, shared scoped retrieval and a generated mini-tool to the future comparison. It supplies concrete optional uses for OpenMontage, Dify and OpenCodeReview, plus desktop references from Wave/AstrBot/OpenHands and coordination patterns from Paperclip. It does not expand the current T13 implementation into these products.

Before adopting code, pin the selected revision, review the relevant source/dependencies/license, run a bounded compatibility fixture, and record results. A popularity count, README feature or passing mock is not admission evidence. Unknown usage, incomplete accounting and unverified containment remain visible in every integration.
