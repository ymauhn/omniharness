## What a later host adapter must prove

Build a coordinator-owned callback facade only after those seams are validated. It must derive identity from verified Docker CID/nonce and exact worktree, pass that to the agent launch, wrap the agent's task report with host evidence, settle the captured stream through `Ledger.settle`, and map `estimated_usd`, disjoint `total_tokens`, `source_sha256`, `usage_complete`, attempt and reservation without model-provided values. Verify exact container removal and worktree audit for every implementer, integrator and reviewer; leave unknown receipts unknown. Test A/B identity, replay, crashes, cancellation and all roles offline. The existing MCP broker **reconstructs** a `ContainerWorker` in its own process while the coordinator keeps another instance; their in-memory locks are not shared. Cross-process serialization or a single owning service is a separate live gate before concurrent managed runs can be admitted.

Independent PR review found one integration contract to resolve in that facade: Swarm labels are shaped like `implement:a:0`, while `container_worker.ATTEMPT` and Claude preparation accept only `[A-Za-z0-9_-]{1,64}`. The facade must derive a separate safe Docker attempt ID while preserving a verifiable one-to-one mapping to the exact Swarm label. Passing the label through unchanged will fail validation; silently normalizing it could alias distinct attempts. Add an adversarial mapping/replay test before wiring the callbacks.

The prepared bridge and broker now both check the same CID/nonce and durable running state. This closes a **model-free identity seam**, not the end-to-end host callback chain.
