Every session starts with a checklist. Nothing spends or reaches the network without your yes.

OmniHarness is a reproducible multi-agent harness for Claude Code, Codex and Hermes: portable skills, a human-in-the-loop gate, a scout that turns a demand into a plan of skills, an adversarial audit loop, an academic layer that never invents a number, and benchmarks that can fail. Open source, MIT.

The flow, over the real skills graph

Scroll the steps; the graph on the right lights the skills each one uses. The graph is not drawn by hand: it is docs/skills-graph/graph.json, generated by skills_graph.py build from every SKILL.md the hosts can reach, embedded at build time. A test fails if a step cites a node the graph does not have.

01Activate

/omniharness loads the rules for this session only, checks the install, reports regressions, and asks the graph which skills this repository needs, so only those bodies get read.

omniharnessskills-graph

02Which skills

The skills graph has three rings: installed, catalog (the marketplace manifest and the curated lists) and remote (awesome lists, fetched only behind the gate). route ranks them for a task at zero tokens; a gap becomes a candidate, never an install.

skills-graphscoutskill-installer

03Research

/scout states the fan-out and its measured cost, waits for the yes, then one agent per source (GitHub, Hacker News, Reddit, X, Product Hunt) returns references with URLs; code dedupes them and one agent writes the dossier of patterns and gaps.

scoutscout-driver

04Interview

The dossier goes to grilling: one round of frontier questions, each with a recommendation. When two routes look viable, one /detour: three alternatives from three worlds, a viability test each, one verdict, then back on the path.

grillingdetourdomain-modeling

05Plan and spec

PLAN.md holds the goal, the success criterion, the routine (each step names the installed skill that runs it) and the gaps; to-spec turns it into a spec, to-tickets into tickets when a tracker exists.

scoutto-specto-tickets

06Environment

/skill-installer plans at zero network: what is done, what is to do with its gate entry, what only the owner can do (a key, a binary). It applies after the yes and registers the result in the graph.

skill-installerimpeccablemagic-mcp

07Build

The design language (impeccable's DESIGN.md) comes before the components; the code is written under the ponytail ruleset: stdlib first, shortest diff, one runnable check per non-trivial piece.

tddponytailimpeccablecodebase-design

08Review

ponytail-review hunts complexity (delete, stdlib, native, yagni, shrink; net lines possible), code-review checks spec compliance, review-security the boundary.

ponytail-reviewcode-reviewreview-security

09Hunt and audit

On demand, or when regress reports a drop: the Gauntlet, hunters per area and refuter lenses until it runs dry, from a git checkpoint. For a manuscript, thesis-review audits against the result files and never invents a number.

gauntlet-loopthesis-review

Members

There is no password on this page and there never will be. The members' edition is a private claude.ai artifact the maintainer shares by hand: opening it is the sign-in, the platform's own account is the identity, and the public edition never carries the member-only text, not even hidden. Zero backend, no credential form, nothing to leak.

  • Members read the prompt guides and the plan template in full, inside the library.
  • Members get the same page, so nothing they learn is out of reach of the public docs on GitHub.
  • To ask for access, open a thread titled "member access" in Discussions; the maintainer shares the edition with your claude.ai account privately.

Your edition

public edition · member guides are links to GitHub
members edition · you are reading through claude.ai

Why not a login form: a form on a static page can only pretend. The honest options on a site with no backend are a platform's own sign-in, an encrypted page with a shared password, or a paid proxy. This page takes the first; the encrypted page is documented for later in the plan.

Detour 1, the library card (physical world). Membership is a token you carry: a share link whose key lives in the URL fragment.
Detour 2, the reading room (screen tradition). The members' material lives only where the platform already knows who is reading.

Contribute

The catalog, the integrations and the graph grow by pull request; the discussions are the community's one door. A row is merged when its URL fetched on the date you name and its numbers are quoted from the source.

  1. Open a PR that adds one row to the right table of docs/catalog/, every column filled, or one [[edge]] to skills-graph.toml with its why.
  2. State the layer it serves and the AGENTS.md routing row it complements, or why none does.
  3. Quote the free-tier numbers with the pricing page URL and the date you read it.
  4. Name the gate entry from harness/settings.json that fires, or "HITL list" when the call has no Bash pattern.
  5. Give the license and any redistribution restriction, and say whether it is security-relevant.
